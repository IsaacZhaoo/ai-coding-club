# Blog Writing Style Guide

**Version:** 1.0
**Last Updated:** 2025-11-04
**Status:** Active
**Internal Document** - Not published in public docs

## Overview

This guide defines the writing style and tone for AI Coding Club blog posts. Our goal is to create a **collaborative community voice** that balances educational authority with approachability, avoiding both overly personal narrative and sterile corporate tone.

## Core Philosophy

### Positioning: Community Learning Platform, Not Personal Blog

**We are not:**
- A personal blog showcasing individual achievements
- An authoritative expert talking down to beginners
- A corporate entity pushing products

**We are:**
- A learning community exploring AI-assisted coding together
- Guides sharing discoveries with fellow learners
- A collaborative space where everyone contributes to collective knowledge

## Voice & Tone Framework

### The "We-You" Dynamic

| Pronoun | Usage | Purpose | Examples |
|---------|-------|---------|----------|
| **We** | Community actions, shared experiences | Creates belonging | "We tested this approach", "We've found that..." |
| **You** | Direct engagement, actionable advice | Empowers readers | "You'll discover", "You can start by..." |
| **I** | Rare, only for attributed quotes | Personal credibility when needed | "Isaac (founder) says...", "In contributor Maria's experience..." |

### Voice Characteristics

| Dimension | Target | Avoid |
|-----------|--------|-------|
| **Authority** | Evidence-based (data, research, community validation) | Personal opinion presented as fact |
| **Expertise** | "We've tested" / "Research shows" | "I'm an expert" / "I know better" |
| **Engagement** | Conversational, direct questions | Academic lecture / Corporate marketing |
| **Emotion** | Authentic struggle & breakthrough | Excessive enthusiasm / Flattery |
| **Call-to-action** | Collaborative invitation | Directive command |

## Writing Patterns

### Pattern 1: Opening Hooks

❌ **Avoid (Personal Authority):**
```markdown
I proved it last month. I gave 5 complete beginners one challenge...
```

✅ **Use (Community Discovery):**
```markdown
Last month, we tested something bold. Five complete beginners joined us
for one challenge: build something useful in 2 weeks using AI coding tools.

Want to know what happened?
```

---

### Pattern 2: Sharing Research/Experiments

❌ **Avoid (Individual Achievement):**
```markdown
I ran an experiment. I was skeptical too, but I discovered that...
```

✅ **Use (Community Validation):**
```markdown
We ran an experiment to answer a question many of us had: does AI really
work for complete beginners?

Here's what we found...
```

---

### Pattern 3: Presenting Credentials

❌ **Avoid (First-Person Expertise):**
```markdown
I've been coding with AI for 2 years. Here's what I learned...
```

✅ **Use (Third-Person or Community):**
```markdown
Our team has been testing AI coding tools for 2 years. Here's what the
data shows...
```

Or if personal story is essential:
```markdown
Isaac (our founder) spent 2 years testing AI coding approaches. His finding:
[insight]. Sound familiar?
```

---

### Pattern 4: Explaining Concepts

❌ **Avoid (Lecture Mode):**
```markdown
You need to understand that AI can't replace system design thinking.
Let me explain why...
```

✅ **Use (Collaborative Exploration):**
```markdown
Here's a question we get a lot: "Can AI handle system design?"

Short answer: Not yet. Here's why this matters for you...
```

---

### Pattern 5: Calls-to-Action

❌ **Avoid (Personal Directive):**
```markdown
I read every issue. Submit your feedback.
```

✅ **Use (Community Invitation):**
```markdown
We read every issue and discussion. Your feedback shapes what we build next.
[Join the conversation →]
```

---

### Pattern 6: Addressing Challenges

❌ **Avoid (Dismissive):**
```markdown
If you refuse to use AI, you'll become obsolete. That's just how it is.
```

✅ **Use (Empathetic + Evidence-Based):**
```markdown
Some developers worry that using AI means they're not "real programmers."
We get it—many of us felt the same way.

But here's what the data shows: [evidence]. The choice is yours, but
here's what to consider...
```

## Style Guidelines

### 1. Pronoun Usage Rules

| Situation | Recommended Pronoun | Rationale |
|-----------|-------------------|-----------|
| Sharing research/experiments | "We tested", "We found" | Community validation |
| Direct instruction | "You can", "You'll discover" | Reader empowerment |
| Platform/team actions | "We built", "We're creating" | Collective ownership |
| User actions | "You start by", "You might try" | Action-focused |
| Attributed expertise | "Isaac says", "Research shows" | Third-person credibility |
| **Avoid almost always** | "I proved", "I discovered" | Too personal/authoritative |

### 2. Evidence Hierarchy

Present evidence in this priority order:

1. **Quantitative data** - "92% of developers use AI tools (GitHub 2024)"
2. **Community validation** - "We tested with 50 beginners, 43 succeeded"
3. **Expert consensus** - "Industry research shows..."
4. **Attributed experience** - "In Isaac's 2-year experiment..."
5. **Logical reasoning** - "Here's why this matters..."

### 3. Emotional Authenticity

✅ **Authentic struggle:**
```markdown
Many of us wasted months learning the wrong way. Sound familiar?
```

❌ **Excessive enthusiasm:**
```markdown
This AMAZING discovery will COMPLETELY TRANSFORM your coding journey!
```

✅ **Honest limitation:**
```markdown
AI can't replace system design thinking—yet. Here's what it can do today...
```

❌ **False promises:**
```markdown
Master coding in 30 days with AI! No prior knowledge needed!
```

### 4. Reader Engagement

Use questions to invite thinking:
```markdown
You might be wondering: "Isn't using AI cheating?"

Here's how we think about it...
```

Acknowledge diverse perspectives:
```markdown
Some of you are excited about AI. Others are skeptical. Both reactions
make sense. Here's what we've learned...
```

## Comparison With Other Platforms

### Refont.ai (Tutorial/Product Focus)
- **Strength**: Clear, step-by-step instructions
- **Limitation**: Less emotional connection
- **What we adopt**: Objective evidence, structured tutorials
- **What we avoid**: Purely transactional tone

### Personal Tech Blogs (Individual Authority)
- **Strength**: Authentic personal stories
- **Limitation**: Not scalable, too egocentric
- **What we adopt**: Story-driven narrative
- **What we avoid**: "I did this, you should too" framing

### AI Coding Club (Hybrid Community Model)
- **Our balance**: Community-validated stories + actionable tutorials
- **Our voice**: "We're exploring this together, here's what works"

## Checklist: Before Publishing

Use this checklist for every blog post:

- [ ] **Pronoun audit**: Count "I" occurrences—should be < 3 total (except in quotes)
- [ ] **"We/You" ratio**: At least 10 instances of "we" or "you" per "I"
- [ ] **Evidence check**: Every major claim backed by data/research/test results
- [ ] **Tone check**: Does it feel like a community guide or personal manifesto?
- [ ] **CTA quality**: Are calls-to-action collaborative ("join us") vs directive ("do this")?
- [ ] **Emotional honesty**: Authentic struggles shared without excessive drama?

## Examples: Full Paragraph Rewrites

### Example 1: Mission Statement

❌ **Original (Personal Authority):**
```markdown
I built AI Coding Club because I wasted 6 months learning the wrong way.
I memorized syntax I immediately forgot. I followed tutorials without
understanding. I felt like an impostor using Stack Overflow.

If that sounds familiar—you're not alone.
```

✅ **Revised (Community Voice):**
```markdown
AI Coding Club exists because many of us wasted months learning the wrong way.
We memorized syntax we immediately forgot. We followed tutorials without
understanding. We felt like impostors asking for help.

If that sounds familiar—you're not alone. Let's fix this together.
```

**Changes:**
- "I built" → "exists because" (removes personal ownership)
- "I wasted" → "many of us wasted" (community shared experience)
- Added: "Let's fix this together" (collaborative invitation)

---

### Example 2: Presenting Research

❌ **Original (Individual Experiment):**
```markdown
I was skeptical too. For months, I heard people say "AI makes coding easier
for beginners," but I didn't believe it would work for *complete* beginners.

So I ran an experiment.
```

✅ **Revised (Community Investigation):**
```markdown
Many of us were skeptical. You've probably heard claims that "AI makes coding
easier for beginners"—but does it really work for *complete* beginners?

We decided to find out.
```

**Changes:**
- "I was skeptical" → "Many of us were skeptical" (shared sentiment)
- "I heard" → "You've probably heard" (engages reader)
- "I ran" → "We decided" (community action)

---

### Example 3: Sharing Insights

❌ **Original (Personal Authority):**
```markdown
I've been coding with AI for 2 years. Here's what it handles:

AI eliminates:
- Writing boilerplate code
- Googling error messages for the 47th time
...

Those skills? More valuable than ever.
```

✅ **Revised (Evidence-Based):**
```markdown
After 2 years of testing AI coding tools across our community, here's what
we've found:

AI handles:
- Writing boilerplate code
- Searching error messages and solutions
...

But here's what it can't replace: [list]. These skills are more valuable
than ever.
```

**Changes:**
- "I've been coding" → "2 years of testing... across our community"
- "Here's what it handles" → "here's what we've found"
- Less declarative, more exploratory tone

## Common Mistakes

### Mistake 1: Disguised "I" Statements

❌ **Still too personal:**
```markdown
We (meaning "me and my team") built this feature...
```

✅ **True community:**
```markdown
This feature was built based on community feedback...
```

### Mistake 2: False Modesty

❌ **Performative humility:**
```markdown
I'm just a beginner myself, but I'll try to explain...
```

✅ **Honest positioning:**
```markdown
This concept can be tricky. Let's break it down together...
```

### Mistake 3: Over-Correction to Corporate

❌ **Too sterile:**
```markdown
Research indicates that utilization of AI-assisted development methodologies
yields productivity improvements...
```

✅ **Conversational + evidence-based:**
```markdown
Here's what the data shows: developers using AI complete tasks 55% faster
(GitHub 2024). What does this mean for you?
```

## Voice Samples

### Opening (Strong Community Hook)

```markdown
Last week, a developer in our Discord shared something fascinating: they
built their first production app in 2 weeks using AI—after failing at
traditional tutorials for 6 months.

Sound too good to be true? We thought so too. So we ran the numbers.
```

### Evidence Presentation

```markdown
We analyzed 50 beginner projects built with AI assistance. Here's what
we found:

- 86% shipped working code within 2 weeks
- 92% reported understanding their code "better than tutorial projects"
- 100% said they'd continue using AI tools

But here's the catch: [nuance]...
```

```markdown
We're building AI Coding Club with input from developers like you. Every
tutorial, resource, and guide reflects what the community actually needs.

**What's your experience?** [Join the discussion →]

**Found this helpful?** [Share your project →]

**See something we missed?** [Open an issue →] — We read every one.
```
