# 四层网站诊断空模板

用你能访问的数据填写，保留在自己的环境中。不要填写账号标识或访客个人信息。可参考[虚构填写示例](./four-layer-diagnosis-fictional-example.zh.md)。

## 1. 确定问题和日期

- 本次想查清的问题：____
- 网站或页面范围，含 hostname 和语言：____
- 目标观察日期，含首尾日期：____ 至 ____
- 可选对照日期，含首尾日期且日历天数相等：____ 至 ____
- 两个窗口的日历天数和星期分布：____
- 采集时间，含时区：____

日期标签相同，时区仍可能不同。下一表记录各后台真正使用的时间边界；只有日汇总时，不声称已完成精确时区转换。比较趋势时，避开尚未完整处理的最近日期，或将窗口标为暂定。

| GA4 | ____ | 属性报告时区：____ | ____ | hostname；着陆页；Session source / medium；国家／设备；比较条件；内部／测试流量处理：____ | ____ |
| 任务事件报表 | ____ | ____ | ____ | 事件名称与触发条件；页面及来源范围；计数单位；埋点版本／生效日期；测试流量处理：____ | ____ |

按实际设置记录筛选。Google 自然搜索会话使用 `Session source = google` 和 `Session medium = organic`；`Organic Search` 渠道总量可能包含其他搜索引擎。首次用户来源与本次会话来源回答不同问题。分别保留 GSC 规范 URL 和 GA4 实际着陆页，说明两者如何对应。

来源总表与页面总表分别导出时，不能据此认定某个着陆页来自哪个来源。需要的联合报表没有取得，就写“未采集”。

Bing 的 `All` 和 `Web and Chat` 可能覆盖传统网页搜索以外的来源，关键词与页面表只含 Web 流量。记录图表总计和表格行时，同时保留来源选择和表格覆盖范围。

## 3. 填写四层证据

每个平台、指标和筛选范围各占一行，按需复制行。Google 和 Bing 分开保留。只有报表明确返回该范围为零时，才填写实测零。

| 层级／来源 | 指标与计数单位 | 观察期 | 对照期，可选 | 证据状态与可比性 | 能支持什么 | 还不能说明什么 |

| 1. 搜索展示／Google | 展示次数 | ____ | ____ | ____ | ____ | ____ |
| 1. 搜索展示／Bing，可选 | 展示次数 | ____ | ____ | ____ | ____ | ____ |
| 2. 搜索点击／Google | 点击次数 | ____ | ____ | ____ | ____ | ____ |
| 2. 搜索点击／Bing，可选 | 点击次数 | ____ | ____ | ____ | ____ | ____ |
| 3. 访问来源／GA4 | 会话数；确切 Session source / medium：____ | ____ | ____ | ____ | ____ | ____ |
| 4. 任务证据／事件报表 | 事件名：____；单位：事件次数／用户数／有事件的会话数：____ | ____ | ____ | ____ | ____ | ____ |

证据状态可填：**已观察、未采集、尚未埋点、不可用、不可比**。空格、缺行和没有后台权限都不等于零。图表总计与导出行和不同时分别记录；查询表可能省略部分行。

事件次数只反映已定义的触发条件。链接点击或下载发起，不能证明文件保存成功、模板填完或读者完成了任务。填写事件实际能够验证的最强结果。

不要把展示、点击、会话和事件相加成总流量，也不要将不同平台的数字相除成转化率或视为同一批人。只有分子、分母、范围、日期与埋点口径兼容且已记录，才比较事件发生率。

## 4. 选定下一项证据

- 同一来源内可比较的观察：____
- 尚未解决的日期、筛选、归因、页面对应或测量差异：____
- 当前证据能支持的有限结论：____
- 最主要的证据缺口：____
- 下一次只查什么，要回答哪个问题：____
- 什么结果会改变当前结论：____
- 等待数据处理后，何时再查：____

写清剩余不确定性和下一次检查，就完成了这张表。流量变化的原因仍然可以未知。
