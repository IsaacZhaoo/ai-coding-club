> TL;DR：用 AI 做项目规划：范围、里程碑与风险。

## 关键步骤
1. 定义最小可用版本（MVP）。
2. 拆里程碑与任务。
3. 写验收标准与测试计划。

## 练习
- 写一个 10 条的 MVP 规格 + 3 条验收用例。

每个伟大的项目都从一个计划开始。在你写第一行代码之前，你需要知道你要构建什么，以及如何构建它。这就是AI可以成为一个不可思议的伙伴的地方，帮助你把一个模糊的想法转化为具体的蓝图。

### 将大想法分解为小任务

像"构建一个待办事项应用"这样的大想法是令人不知所措的。第一步是将其分解为较小的、可管理的任务。这是一个AI助手完美的工作。

> "我想构建一个待办事项网络应用。我是初学者。你能把这个项目分解成一个简单、可行的任务清单吗？"

### 定义你的MVP（最小可行产品）

你不能一次性构建所有功能。你需要定义你的MVP：产品的最简单版本，它仍然能工作并提供价值。对于我们的待办应用，MVP可能是：

- 用户可以看到任务列表。
- 用户可以向列表添加任务。
- 用户可以将任务标记为完成。

就这样。没有用户账户、没有截止日期、没有花哨的动画。从MVP开始，稍后添加功能。

### 文件和文件夹结构

干净的项目结构使你的代码更容易管理。你可以向AI询问最佳实践。

> "对于包含HTML、CSS和JavaScript的简单网络应用，什么是一个好的文件和文件夹结构？"

通常，你会有：

```
/project-root
|-- index.html
|-- /css
|   |-- style.css
|-- /js
    |-- main.js
```

### 用户故事和功能列表

- **用户故事：** 从用户角度对功能的简短、简单描述。示例："作为用户，我想能够添加任务，这样我就能记住我需要做的事情。"
- **功能列表：** 应用需要做什么的更技术性列表。示例："创建一个输入字段和一个按钮来添加新任务。"

AI可以从简单描述生成这些内容。

### 轮到你了：规划你的项目

想一个你想构建的简单应用。它可以是一个博客、一本食谱书或个人网站。现在，使用你的AI助手创建一个项目计划。

1. 写一个你应用的单句描述。
2. 请AI为你定义一个MVP。
3. 请AI生成一个用户故事列表。
4. 请AI创建一个推荐的文件和文件夹结构。

保存这个计划。在下一课，我们将开始构建！
