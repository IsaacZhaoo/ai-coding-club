> TL;DR：用 Netlify 手动上传部署一个纯静态 HTML 工具，并在独立浏览器中验证访问与记录隔离。

## 关键步骤
1. 准备项目文件夹与 index.html（必须为根目录的 index.html）。
2. 通过 Netlify Drop 上传并确认部署成功。
3. 检查可见性：让未登录访客打开主地址，核对页面正常显示。
4. 复核数据边界：对比不同浏览器配置的访问情况与 localStorage 保存规则。

## 练习
- 上传 expense-site（代码中不含三笔记录）。在该项目的正式发布主地址、使用你惯用的持久浏览器配置，手动录入三条虚构记账记录：午餐/12.50、公交/8.00、笔记本/5.00。随后打开一个此前未用于该地址的独立浏览器配置访问同一主地址，确认工具界面正常但记录为空，以此验证数据仅存于原配置的 localStorage。
- 写一份 5 条以内“部署后检查清单”，供后续任何静态工具上线时复用。

## 1. 部署目标与平台选择
如果你的工具只是 HTML/CSS/JavaScript（没有后端、没有数据库、不需要编译），那么部署的本质很直接：把资源放到服务器并对外提供 HTTPS 链接即可。

常见且对静态项目友好的平台：
- **Netlify**：以手动上传和更新体验友好著称，适合快速上线与迭代。

本教程选择 **Netlify 手动上传**，因为：
- 无需 Git 仓库、Node.js、构建步骤或命令行。
- 只要求一个可运行的文件夹和 index.html，拖入即部署。

> 需要一个小前提：你拥有一个能正常在本地打开的 HTML 工具（例如之前完成过的支出记事本）。它是静态页面，刷新就能用。

## 2. 准备项目文件夹
### 2.1 新建结构
- 在你的电脑上创建一个新文件夹，命名为 `expense-site`（其他名称也可，但教程以它为例）。
- 在这个文件夹内，把你的工具的主页面保存为 **index.html**，不要嵌套在其他目录里。
  - ✅ 正确：`expense-site/index.html`
  - ❌ 错误：`expense-site/tools/expense-tool.html` 或 `expense-site/index.html.txt`

### 2.2 确认文件与资源
- 打开 `expense-site`，在文件管理器中显示扩展名，确保文件名为 `index.html`。
- 如果你的工具引用了外部 CSS、JavaScript 或图片，把它们放进同一文件夹或相对子目录，保持文件名与大小写一致（例如 `style.css`、`app.js`）。
- 电脑上本地路径如 `C:\Users\…` 或 `file:///…` 不能直接分享；部署后你需要的是公网的 HTTPS 地址。

### 2.3 使用示例 HTML（可选但推荐）
如果当前页面不确定是否“可部署”，可以直接使用备份恢复教程中的参考代码：
- 源地址：https://raw.githubusercontent.com/IsaacZhaoo/ai-coding-club/f4546897549e20afde5d76e3ddf2ac5b6d668207/examples/html-tool-backup-restore/expense-tool.html
- 操作：
  - 在浏览器打开这个 raw 链接；
  - 右键 → “另存为”，保存名为 `index.html`；
  - 将文件放入 `expense-site` 文件夹。

该示例把样式与脚本内嵌于 HTML 单文件中，部署后无需额外配置。它支持切换中文（如主地址后加 `?lang=zh`），方便你在后续验证时对照界面。

## 3. 通过 Netlify Drop 上传
### 3.1 登录与入口
1. 访问 [https://app.netlify.com](https://app.netlify.com) 并用浏览器打开。
2. 注册或登录（GitHub、Google 等方式均可）。
   - 新账号会进入团队视图，你将成为该项目的管理员/所有者。

### 3.2 手动上传
有两种等效入口（任选其一）：
- 直接上传：[https://app.netlify.com/drop](https://app.netlify.com/drop)
- 或：Projects → Add new project → Deploy manually

在 Drop zone 中操作：
1. 打开文件管理器，找到 `expense-site` 文件夹。
2. 把整个 **expense-site** 文件夹拖入 Netlify 的 Drop zone。
   - 注意：不要只拖里面的某个子文件夹；上传根目录即可。
3. 等待部署进度条完成。通常几分钟内就会生成一个主地址（以 `netlify.app` 结尾）。

> 提示：保持文件名与大小写不变。如果最终地址加载时样式或图片缺失，常见原因是资源路径错误或某文件未一起上传。

## 4. 让访客能访问：检查可见性
### 4.1 默认隐私设置
新项目的可见性取决于团队默认设置与方案，可能从私有开始，部署成功并不意味着游客能直接访问该页面。
- 部署成功 ≠ 游客能打开。
- 必须明确把生产部署设为公开。

在 Netlify 中操作：
在已完成一次成功 production deploy 后，可以通过以下官方支持的步骤将生产版本公开：
- 在项目中选择 Make public，即可公开生产版本；或
- 进入 Project configuration → General → Visitor access → Project visibility，设置生产版本的可见性。

> 改名提示：Make public 有时也会提供项目改名的选项。为了避免 hostname 变化影响后续验证与链接使用，建议：
- 先确定并记好最终的主地址；
- 或先把需要搬运的 localStorage 记录导出为 JSON（保留原地址与原浏览器配置），再做公开/改名操作。
如需一次完成改名与公开，可参考 Netlify 官方文档：https://docs.netlify.com/manage/security/secure-access-to-sites/project-visibility/ 。

### 4.2 独立浏览器验证
用“未登录 Netlify 且配置干净”的浏览器窗口打开主地址：
- 推荐方式：新开的无痕/隐私模式，或另一台设备。
- 预期结果：页面直接显示工具界面，无需登录访客账号。

这一步的目的不是测试“能不能保存数据”，而是确认：
- 纯静态资源被正确托管；
- HTTPS 自动生效；
- 没有因可见性设置导致跳转到登录页。

## 5. 复核浏览器记录边界（为什么你的记录不会“随上传泄露”）
### 5.1 localStorage 的保存规则
本教程选用的支出记事本参考中，HTML 文件内已嵌入了小程序逻辑，而你的支出记录则被保存在浏览器的 localStorage 里。这意味着你只需上传这个 HTML 参考文件本身，并不会顺带把那些私人的记录也传上去。不过，如果你打算换用自己的工具来运行，记得先核对它：是否在源文件内部存储数据？是否通过网络向外发送记录？只有确认无误后，才能直接沿用本参考的结论。接下来看的是 localStorage 的数据隔离规则——它并非全局共享，而是依据浏览器的配置以及 origin（即协议 + 主机名 + 端口组合）来分别存取的。
- 只改 URL 路径不会换存储空间。
- 同一配置多开标签页共享同一存储，不独立。
- 不同 hostname、端口、HTTP/HTTPS、另一配置或设备不会自动共享记录。
- file URL 的存储行为因浏览器而异，不作跨浏览器或移动文件后的保证。
- 首次在一个此前未使用过的新配置和新地址组合打开本工具时，记录为空。
https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage

### 5.2 三笔虚构记录的对照验证
为了让边界更直观，请在**你自己的浏览器配置**中录入以下三笔记录：
- 2026-11-01 / Lunch / 12.50
- 2026-11-02 / Bus / 8.00
- 2026-11-03 / Notebook / 5.00

预期：
- 该配置下打开主地址，能看到工具与三条记录（合计 25.50）。
- 刷新后数据仍在；关闭页面再打开仍存。

然后，用**一个此前未用于该地址的独立浏览器配置**（或无痕窗口）访问同一个主地址：
- 预期：显示工具界面，但记录为空。
> 注意：隐私窗口的记录可能随窗口关闭而清除，不能承诺其重新打开后仍保留。

## 6. 备份与恢复：分享工具但不分享个人记录
搬运记录的简短可执行序列：
- 从原地址、原浏览器配置导出 JSON 到磁盘，放在 expense-site 外；JSON 可直接阅读、未加密。
- 打开最终发布的 Netlify 主地址和目标浏览器配置；若目标已有要保留的记录，先将其导出。
- 选择从原地址导出的源记录 JSON 并确认恢复；本参考在确认后替换全部当前记录，不合并。
- 逐项核对日期、说明、金额、笔数、合计，刷新后再确认无误。
- 见链接：[备份与恢复教程](https://aicoding.club/zh/docs/tutorials/html-tool-backup-restore/)；朋友试用时输入自己的虚构记录即可，无需你的个人 JSON。

## 7. 同项目更新程序
更新前导出需要保留的浏览器记录，并保留上一版程序文件。
打开同一个 Netlify 项目的 Deploys，将完整更新后的 expense-site 文件夹重新上传到该项目 dropzone；不要跳转至新项目的 Drop 入口。
用原主地址检查预期界面变化，刷新页面，再确认记录仍然可读。
旧记录能继续读取的条件：同一 origin 和浏览器配置、存储 key 不变、格式兼容；改 hostname、key 或格式，或清除浏览器数据，会改变结果。
更新程序并没有为浏览器记录做备份；记录仍要显式导出与恢复。
https://docs.netlify.com/manage/projects/add-new-project/

## 8. 排错速查（按症状定位）
- **404 / 空白页**：检查上传根目录的 `index.html` 是否存在；确认没有 `index.html.txt` 或大小写拼写错误。
- **样式/图片缺失**：确认所有资源与 HTML 一起上传，路径正确，且大小写一致。
- **访客看到登录页**：检查 Project visibility，确保 production deploy 已设为公开。
- **换主机名/配置后记录为空**：确认 localStorage 是按 origin 隔离的，改 hostname、HTTP/HTTPS 切换、或不同浏览器配置都会导致新环境无历史数据；需重新录入或通过备份恢复。
- **向 AI 求助时**：提供准确报错信息、目录树（如 `expense-site/index.html`）、主地址或资源失败提示；避免夹带账号凭据与个人 JSON 内容。

## 9. 预算与实际限制
本练习可以使用提供的 netlify.app 地址直接部署运行，无需购买或配置自定义域名。Netlify 提供免费的托管方案，但该方案包含一个随月计量的 credit 额度；生产环境部署、页面流量以及 请求等都会消耗这个用量。当前具体的定价与免费配额可能因你的账户或套餐而异，建议通过 [Netlify Pricing](https://www.netlify.com/pricing/) 查看适用于你场景的最新方案。

## 10. 总结：你已拿到可用链接与验证能力
完成以上步骤后，你将拥有：
- 一个可对外访问的 HTTPS 主地址（以 `netlify.app` 结尾）；
- 一套从上传、公开设置到访客验证的完整流程；
- 对浏览器记录边界的清晰认知：线上地址只是载体，数据仍由具体浏览器配置管理。

下一步建议：
- 把这个“部署后检查清单”固化下来，用于后续任何静态工具上线；
- 把方法迁移到你自己的工具中（无论是待优化的记账应用，还是其他小型前端项目）。

## 附录：部署后检查清单（5 条）
1. 用独立浏览器/无痕窗口打开主地址，确认无需登录即可看到工具界面。
2. 刷新两次，观察数据（如记账记录）是否稳定显示。
3. 用一个未登录的全新浏览器配置访问同一地址，确认本地记录为空。
4. 在 Netlify Deploys 中查看最新一次 production deploy 的状态为 Success，且没有明显错误日志。
5. 确认所有引用资源（CSS/JS/图片）加载正常，无 404 或跨域提示。
