## 1) 实施计划（含文件与 DoD）

```text
为这个任务写一份实施计划：
[TASK]

约束：
- diff 尽量小
- 列出要改的具体文件
- 给出 Definition of Done 和验证命令

输出格式：
1) 假设/问题
2) 分步计划
3) 文件清单
4) 风险与缓解
5) 验证清单
```

## 2) Bug 调查计划

```text
我遇到一个 bug，请给调查计划。

Bug：
- 现象： [SYMPTOM]
- 报错/日志： [LOGS]
- 最近改动： [CHANGES]

输出：
- 按可能性排序的假设
- 需要收集的证据
- 建议运行的命令
- 如何确认修复有效
```

## 3) 兼容迁移计划（旧 -> 新）

```text
规划从 [OLD] 迁移到 [NEW]。

约束：
- 尽量向后兼容
- 尽量无停机
- 必须包含回滚步骤

返回：
- 分阶段迁移步骤
- 数据/Schema 注意点
- 需要监控的指标/告警
```

## 4) 合并前风险审查

```text
合并前请做一次风险审查。

上下文：
- 目标： [GOAL]
- 变更文件： [FILES]
- Diff： [PASTE DIFF]

输出：
- Top 风险
- 最坏故障模式
- 缓解措施
- 额外需要跑的测试/检查
```

## 5) 发布清单

```text
为这次变更写发布清单。

包含：
- 发布前检查
- 部署步骤
- 部署后验证
- 回滚方案

变更摘要：
[SUMMARY]
```

## FAQ

### 什么样的计划算可执行？

范围清晰、文件明确、步骤可落地，并且每一步都有验证方式。

### 怎么降低风险？

分步推进、最小改动、包含回滚策略，并要求验证闭环。

### 上下文不够怎么办？

先提澄清问题，并要求先读文件再改动。
