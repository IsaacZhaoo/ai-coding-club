# Claude Code 新手指南：第一次让 AI 在你的项目里安全干活

## TL;DR

Claude Code 适合拿来做那种需要读懂项目的任务，比如解释项目结构、修 bug、重构、补测试和更新文档。新手不要一上来让它“大改项目”，先从一个小任务开始，保留 Git 检查点，review diff，再运行验证命令。

## 适合谁

- 已经有一个本地项目，想让 AI 帮你读代码、改代码、跑命令。
- 能看懂基本 diff，愿意在接受改动前做人工 review。
- 想学习 terminal-first 的 AI 编程工作流，而不是只用聊天窗口复制粘贴代码。

## 快速决策指南

先不要问“Claude Code 是不是最强”。更实用的判断是：

- 如果你需要工具读懂项目、跨文件定位问题、运行命令和修改代码，可以尝试 Claude Code。
- 如果你还没有本地项目，只有一个模糊想法，先用聊天窗口或文档把需求拆清楚。
- 如果你完全不打算看 diff，也不打算运行测试，先不要把 Agent 接入真实项目。
- 如果你正在处理敏感密钥、生产数据库或客户资料，先弄清权限边界和备份策略。

## 安装与登录前提

常见安装方式如下，如果遇到问题可以打开官方 quickstart 核对。

macOS / Linux / WSL：

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows 用户按官方 PowerShell、CMD 或 WinGet 指引安装；macOS 也可以用 Homebrew cask。

账号方面，Claude subscription 或 Anthropic Console 账号都可以登录。安装完成后进入项目目录，运行 `claude`，按提示登录，或用 `/login` 命令。

## 第一次使用的安全流程

1. 从项目根目录开始，先运行 `git status`。
2. 如果已有未提交工作，先提交、stash，或创建一个独立分支/检查点。
3. 先让 Claude Code 解释项目，不要立刻改文件。
4. 给一个小任务，例如修一个表单校验 bug。
5. 要求它先说明计划，再修改。
6. 修改后运行 `git diff`。
7. 检查改了哪些文件，是否有无关重写、密钥、配置变更或被删除的关键逻辑。
8. 运行项目已有的 lint、typecheck、test 或 build。
9. 只有 review 和验证都通过后，再接受改动并提交。

## 第一个推荐 Prompt

```text
请先阅读这个项目，告诉我：
1. 主要目录分别做什么；
2. 本项目如何运行和构建；
3. 如果我要修一个小 bug，你建议我先看哪些文件；
4. 先不要修改任何文件。
```

## 第一个修改型 Prompt

```text
请修复这个小问题：[描述具体问题]。

要求：
- 先定位相关文件并说明计划；
- 做最小改动；
- 不重构无关代码；
- 修改后告诉我应该运行哪些验证命令；
- 如果无法确认，请明确说哪些部分需要我人工检查。
```

## 新手最容易犯的错误

- 任务太大，一次让它做完整系统。
- 不看 diff，直接接受改动。
- 不运行验证命令。
- 把长期规则每次都写在 prompt 里，而不是沉淀到项目说明文件。
- 在不了解权限边界时给过高权限。

## 和 Cursor、Copilot、Codex 怎么分工

Copilot 常见使用场景是补全、编辑器内问答和轻量 agent 辅助；Cursor 更偏编辑器内多文件协作；Claude Code 的主场是终端里的多步骤任务。Codex 更适合已经在 OpenAI / ChatGPT 生态里的 agentic coding 工作流。

## 常见问题

### Claude Code 适合新手吗？

适合，但前提是从小任务开始，并且把 review diff 和运行验证当成流程的一部分。

### 我需要一开始就学高级配置吗？

不需要。先掌握“描述目标、让它先理解项目、做最小改动、验证结果”这一条主线。

### Claude Code 能替我完全写代码吗？

它可以生成和修改很多代码，也能大幅提高执行效率；但需求判断、架构取舍、代码 review、结果验证和安全责任仍然需要人来负责。
