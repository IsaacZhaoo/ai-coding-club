# 为单文件 HTML 小工具增加可验证的数据备份与恢复

保存 HTML 程序文件并不会自动包含浏览器记录的更改。本教程的做法是：用练习副本添加一个 JSON 备份，导出后在“空环境”里导入核对。

- 在练习副本上让 AI 给现有工具加上“导出备份”和“恢复备份”。
- 用实际下载下来的 JSON 文件，在一个干净的浏览器环境里恢复并核对数据。
- 确保三笔虚构支出正确：3 笔、合计 25.50 元；恢复后刷新还在；同一备份再导入仍为三笔；错误文件能保留原记录不动。

主题很直接：**HTML + JSON + localStorage**，在单文件无外部依赖的前提下实现：
- **导出：** 把当前内存里的数据写成一条标准 JSON 快照，保存到本地。
- **恢复：** 上传一个 JSON 备份，先校验再替换（不是合并），保证“确认生效前数据不丢”。

下面的所有测试、命令和示例都是围绕同一套练习文件展开的。你可以复制它们到自己的电脑，按步骤来。

## 一、准备工作：搭建只用于练习的本机 HTTP 服务

我们不需要部署到公网，也不要在浏览器里直接双击 HTML 文件做复杂操作（file://协议对 localStorage 和跨标签页共享并不友好）。我们只用本机的小 HTTP 服务，让浏览器在同一台电脑上用标准的 `http://127.0.0.1:8765/` 访问。

### 1. 新建练习目录

在你的电脑上创建一个专门放“练习文件”的文件夹，例如：

- Windows：`C:\Users\你的用户名\ai-coding-club-practice`
- macOS / Linux：`~/ai-coding-club-practice`

先准备好以下三个文件（它们就是你要使用的“下载文件”），然后全部保存到同一个新建的练习目录中：
- <a href="https://raw.githubusercontent.com/IsaacZhaoo/ai-coding-club/f4546897549e20afde5d76e3ddf2ac5b6d668207/examples/html-tool-backup-restore/starter.html">starter.html</a>：起始工具副本。
- <a href="https://raw.githubusercontent.com/IsaacZhaoo/ai-coding-club/f4546897549e20afde5d76e3ddf2ac5b6d668207/examples/html-tool-backup-restore/expense-tool.html">expense-tool.html</a>：参考完成版。
- <a href="https://raw.githubusercontent.com/IsaacZhaoo/ai-coding-club/f4546897549e20afde5d76e3ddf2ac5b6d668207/examples/html-tool-backup-restore/sample-backup.json">sample-backup.json</a>：固定三笔样例数据。

> 注意：这里的 `starter.html` 是你后续让 AI 改代码的起点。不要误删或覆盖它，除非你清楚自己在做什么。

### 2. 启动本地 HTTP 服务器

在该目录打开终端（PowerShell / Terminal / Git Bash），确认已安装 Python 3：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

你会看到类似输出：

```text
Serving HTTP on 127.0.0.1 port 8765 (http://127.0.0.1:8765/) ...
```

- **保持这个终端运行**。这是你的“后台”，不要关掉。
- 结束练习时，按 `Ctrl + C` 停止服务即可。

> 重要提示：
> - `127.0.0.1` 是当前这台电脑自己的地址。另一台设备连不上它。
> - 编辑时只保持一个工具标签页，避免多个页面同时操作造成状态不同步。
> - 这个服务只是“本地练习”，不是面向公开访问的网站部署。

### 3. 在浏览器里打开练习工具

在同一台电脑的桌面浏览器（Chrome / Edge / Safari / Firefox 均可）中：

- 打开新标签页，输入：`http://127.0.0.1:8765/starter.html`
- 你看到的就是起始工具的界面。先不用急着改代码，先熟悉它的基本行为。

## 二、理解工具现状：保留原功能，再增加备份能力

### 1. starter.html 已经具备的功能

从 `starter.html` 的界面可以看出来（以中文为例）：

- 可以添加支出记录：
  - 日期、说明、金额
- 点击“添加”按钮后的实际执行顺序是：先成功写入 localStorage，再更新内存中的记录和界面；如果写入失败，则保留原来的状态（记录与显示都不变）。这是程序已实现的事实逻辑。
- 可以逐条删除某条记录
- 刷新页面后，保存的记录仍然在（靠 localStorage）
- 可以选择显示语言：英文 / 中文
- **尚无备份功能**：没有导出 JSON，也没有上传恢复入口

这个“增删 + 刷新保留”的能力已经足够做一个轻量记账工具。问题是：**一旦浏览器清理了 localStorage、换了设备、或者误操作清空数据，当前内存里就没了。** 这就是我们要增加“可验证的数据备份与恢复”要解决的问题。

### 2. 参考完成版 expense-tool.html 给我们的目标

打开另一个标签页：`http://127.0.0.1:8765/expense-tool.html`

你会看到界面多了两个关键按钮/控件：

- 中文：
  - “导出备份”按钮
  - “选择要恢复的 JSON 备份”文件选择框
- 英文：
  - “Export backup”
  - “Choose JSON backup to restore”

功能约定：

- **导出：**
  - 点击“导出备份”，浏览器会下载一个名为 `expenses-backup.json` 的文件。
  - 这个文件是**当前记录的一条完整快照**。
- **恢复：**
  - 选择文件后，工具会先校验 JSON 格式与结构；
  - 校验合法时弹出一个确认框：“是否用此备份替换当前数据？”
  - 用户确认后，整份数据被替换（不是合并），并刷新或更新界面。

如果你现在把 `starter.html` 里的数据保存几条，去打开 `expense-tool.html`，你会发现：只要在同浏览器、同协议（`http://127.0.0.1:8765`）、同端口下访问，两者共享相同的 localStorage 键 `aicodingclub-expenses-v1`。所以你在 starter 里存的数据，能在 expense-tool 中读到；反过来也一样。

> 关键点：
> - localStorage 是按“origin（协议+主机+端口）”和“浏览器配置/隐私窗口”隔离的。
> - 路径不同（starter.html vs expense-tool.html）本身不会隔离数据。
> - 这意味着：**备份文件的 app 字段是 `aicodingclub-expenses`，而 localStorage 存储键是 `aicodingclub-expenses-v1`，两者可以不一样。** 你自己的工具实现时，一定要先查实际格式与键，不能盲目替换。

## 三、固定练习数据：三笔虚构支出，逐字段核对

为了让后续测试有明确预期，我们约定三笔固定的支出（人民币 CNY）：

- 2026-11-01 Lunch：12.50 元
- 2026-11-02 Bus：8.00 元
- 2026-11-03 Notebook：5.00 元

合计：**25.50 元**，共 **3 笔**。

重要约定（全部用于后续核对）：

- 金额使用 `amountCents` 存储为整数分：
  - 12.50 元 → 1250
  - 8.00 元 → 800
  - 5.00 元 → 500
- 所有日期格式固定为 `YYYY-MM-DD`，例如 `2026-11-01`。
- 每条记录必须包含：
  - `id`（唯一非空字符串）
  - `date`（真实日期，非空）
  - `label`（非空说明文字）
  - `amountCents`（正整数分）

你可以先在 starter.html 里手动录入这三笔数据：

1. 添加：2026-11-01，Lunch，12.50
2. 添加：2026-11-02，Bus，8.00
3. 添加：2026-11-03，Notebook，5.00

然后刷新页面，核对：

- 列表里显示 3 条；
- 每条的日期、说明、金额都正确；
- 合计应该是 25.50 元（如果界面有合计显示）。

> 提醒：只看“合计 25.50”是不够的。必须逐条核对日期/说明/金额，确保没有乱序、重复或异常数据混入。

## 四、让 AI 为 starter.html 增加导出与恢复功能

现在进入核心环节：**在 starter.html 的练习副本上，让 AI 加上备份能力。**

### 1. 选择你的开发方式

你有两种常见场景：

- **普通聊天机器人**（网页对话）：
  - 不能直接访问你本地的 `C:\Users\...\starter.html`。
  - 需要你把 HTML 的完整内容复制粘贴到对话中，或把文件上传到对话支持的文件读取功能里。
  - 然后让 AI“保留增删、刷新保存、语言切换”的所有功能，增加单文件 JSON 导出与恢复。

- **代码编辑器中的 AI 助手**（如 VS Code + Copilot / Cursor / 等）：
  - 如果你把整个练习目录放入工作区，且该助手支持读取本地文件，你可以直接指定它读取 `starter.html`。
  - 这样它可以看到你的真实项目结构，方便生成与上下文更贴合的修改方案。

无论哪种方式，请确保：
- **原 `starter.html` 不动**（除非你明确要做版本覆盖）。
- AI 返回的 HTML 保存为 `my-expenses.html`。

### 2. 给 AI 的需求说明（建议直接复制这段）
````markdown
构建一个自包含的 HTML 消费记账小程序，基于完整 HTML 副本实现“导出/恢复”功能，返回仍为自包含 HTML。程序需：
- 保留当前记录列表和增删、刷新、语言切换等操作；
- 无外部依赖（如 CDN）、无云端同步；
- 使用 localStorage 的存储键为：aicodingclub-expenses-v1；
- 导出的 JSON 结构必须包含且符合以下约定字段：
  - app: "aicodingclub-expenses"
  - version: 1
  - currency: "CNY"
  - records: 数组，最多 1000 笔，每条记录包含：
    - id: 非空唯一标识；
    - date: 真实日历日期，格式 YYYY-MM-DD；
    - label: 非空，最多 80 字符；
    - amountCents: 正整数，表示“分”，上限 100000000（即 100 万元）；
  - 文件与规范导出大小限制为 ≤1MiB；
- 导入/恢复前：先完整校验 JSON 结构与数值范围，全部合法后再确认“当前/导入笔数”和“当前/导入总计”；
- 用户确认后：必须先成功保存（写入 localStorage），再更新内存显示；
- 取消操作、无效输入或保存失败时：均保留原有记录与界面状态不变；
- 导出时默认文件名为 expenses-backup.json，允许 records 为空数组。
````

### 3. AI 返回后：保存并加载到你的练习目录

AI 给出完整 HTML 代码后：

1. **复制整个 `<html>...</html>` 片段**；
2. 在你的练习目录下新建文件 `my-expenses.html`；
3. 将代码粘贴进去，保存。

然后回到浏览器：

- 在之前运行的 HTTP 服务终端里确认仍在运行（看到 `Serving HTTP on...`）；
- 打开新标签页：`http://127.0.0.1:8765/my-expenses.html`

你看到的就是带有导出/恢复功能的新工具。

## 五、第一次实战：从“空环境”恢复并核对三笔 25.50 元

这一步非常关键，用来验证你的实现是否正确，以及备份文件是否真的“可迁移”。

### 1. 准备一个“干净”的浏览器环境

在同一台电脑上，做以下任一操作（目的是让 localStorage 里没有之前练习留下的记录）：

- 使用**隐私/无痕窗口**打开新标签页；
- 或使用另一个从未用过该练习工具的独立用户配置文件；
- 注意不要只是“刷新页面”，那样仍共享同一个 localStorage。

在这个空白环境中，访问：

- `http://127.0.0.1:8765/expense-tool.html`（或用你自己的 `my-expenses.html`）

你应当看到：

- 界面正常；
- 记录列表为空，合计为 0；
- 没有任何“导入成功”的弹窗。

这一步证明：**新环境确实没有继承旧记录的 localStorage**。

### 2. 确认导出的 JSON 文件真实存在且正确

回到另一个标签页（或原浏览器窗口），用你改好的工具：

1. **录入新记录（仅在空的练习源环境中执行）**
   - 先检查改好的工具是否已经从 starter 里共享过那三笔样例；若已有则不重复添加。
   - 只在确认“当前环境为空”的前提下，依次录入：
     - 2026-11-01 Lunch 12.50 元
     - 2026-11-02 Bus 8.00 元
     - 2026-11-03 Notebook 5.00 元
2. 点击“导出备份”。
3. 通过浏览器菜单打开下载列表：使用浏览器的“下载”管理界面查看刚导出的 expenses-backup.json。
   - 确认出现一个名为 `expenses-backup.json` 的文件；
   - 状态为“已下载”或“完成”。
4. 去实际的文件管理器（文件资源管理器 / Finder）里查看下载目录，确认真正生成了这个文件。
5. 右键打开该 JSON 文件（用记事本、文本编辑器等），核对内容类似：

```json
{
  "app": "aicodingclub-expenses",
  "version": 1,
  "currency": "CNY",
  "records": [
    {
      "id": "sample-1",
      "date": "2026-11-01",
      "label": "Lunch",
      "amountCents": 1250
    },
    {
      "id": "sample-2",
      "date": "2026-11-02",
      "label": "Bus",
      "amountCents": 800
    },
    {
      "id": "sample-3",
      "date": "2026-11-03",
      "label": "Notebook",
      "amountCents": 500
    }
  ]
}
```

> 提示：
> - 不要只看“导出成功”的提示。
> - 必须看到真实下载的文件，并且能用编辑器打开、可读且结构正确。

### 3. 在“空环境”里恢复并逐字段核对

回到那个“干净”的浏览器配置（或隐私窗口），再次访问：

- `http://127.0.0.1:8765/expense-tool.html`（或你的新工具）

步骤：

1. 点击“选择要恢复的 JSON 备份”。
2. 浏览到刚才下载下来的 `expenses-backup.json`，选中它。
3. 观察界面：
   - 应出现校验通过的提示；
   - 然后弹出确认框：“是否用此备份替换当前数据？”
4. 点击“确认”（或对应的按钮）。
5. 等待刷新/更新后核对：
   - 列表里显示 **3 笔**；
   - 日期、说明、金额逐条与备份文件一致；
   - 合计为 **25.50 元**。

这一步说明：**从空环境到导入，备份是“完全且可验证”的快照，不是模糊的提示。**

### 4. 刷新页面再次核对

在同一标签页：

- 按浏览器地址栏的“刷新”按钮，或 `Ctrl + R` / `Cmd + R`。
- 观察：
  - 仍然显示 3 笔；
  - 金额与日期没有丢失或错位；
  - 合计仍为 25.50 元。

这验证了：**恢复后的数据在 localStorage 中稳固存在**，不会因为刷新而消失（前提是浏览器没有主动清除）。

## 六、再导入同一备份：恢复是“快照替换”，不是自动合并

现在测试一个重要的边界行为：**恢复是整份替换当前内存里的记录，而不是自动合并**。

### 1. 初始状态确认

在浏览器工具中，你应该已经有这 3 笔数据（合计 25.50 元）：
- 2026-11-01，Lunch，12.50
- 2026-11-02，Bus，8.00
- 2026-11-03，Notebook，5.00

### 2. 直接重复导入同一份备份：确认“替换”行为

回到“选择要恢复的 JSON 备份”功能：

1. 再次选择刚才那个 `expenses-backup.json`；
2. 校验通过后，又弹出确认框：“是否用此备份替换当前数据？”
3. 这次点击“确认”。

结果应该是：
- 记录数量仍为 **3 笔**；
- 合计仍为 **25.50 元**。

这一步说明：**对同一份快照连续操作，恢复就是精确替换，不会合并或报错**。

### 3. 新增一条记录，看到总数变化

在当前页面上：

1. 新增一条支出：
   - 例如：2026-11-04，Coffee，1.00
2. 刷新页面：
   - 现在应该有 **4 笔**，合计 **26.50 元**。

这一步确认了：**工具仍然可以正常增删、刷新保存**。

### 4. 先取消恢复，核对新增记录
此时上一小节已添加 Coffee 1.00 元，共 4 笔、总计 26.50 元。按以下顺序操作：
- 选择旧的“三笔样例备份”进行导入；
- 先点击“取消恢复”，刷新核对仍显示 4 笔/26.50 元；
- 如需保留这 4 笔，请另存一个与旧备份**不同文件名**的 JSON，确认两份文件都存在；
- 再选择原始三笔旧备份进行导入，确认替换并刷新回 3 笔/25.50 元（Coffee 不再出现）；


## 七、错误文件测试：破坏性备份必须被拒绝且保留原记录

现在验证工具的健壮性：**如果用户导入一个格式错误或内容损坏的 JSON，系统应拒绝替换，并且保留原有记录。**

### 1. 用 version 不匹配破坏校验

在你的练习目录中，复制 `sample-backup.json`（或你导出的那份）为：

- `backup-bad-version.json`

用文本编辑器打开它，把 `"version": 1` 改成 `"version": 2`，然后保存：

```json
{
  "app": "aicodingclub-expenses",
  "version": 2,
  "currency": "CNY",
  "records": [
    {
      "id": "sample-1",
      "date": "2026-11-01",
      "label": "Lunch",
      "amountCents": 1250
    },
    {
      "id": "sample-2",
      "date": "2026-11-02",
      "label": "Bus",
      "amountCents": 800
    },
    {
      "id": "sample-3",
      "date": "2026-11-03",
      "label": "Notebook",
      "amountCents": 500
    }
  ]
}
```

然后在工具中：

1. 选择 `backup-bad-version.json`；
2. 如果校验逻辑正确，应该**直接拒绝**（或显示“备份未通过检查，现有记录已保留。”），而**不会弹出确认框**。
3. 刷新页面：仍显示你之前的 4 笔或 3 笔数据，没有变化。

### 2. 用语法错误破坏 JSON

再做一次更粗暴的测试：

- 复制 `backup-bad-version.json` 为 `backup-bad-syntax.json`；
- 在末尾添加一个多余的逗号或括号，例如：

```json
{
  "app": "aicodingclub-expenses",
  "version": 2,
  "currency": "CNY",
  "records": [
    {
      "id": "sample-1",
      "date": "2026-11-01",
      "label": "Lunch",
```

## 八、概念与边界：避免常见误区

这部分是给你的“经验值”，防止你在使用和迁移工具时踩坑。

### 1. HTML vs JSON：代码 vs 数据快照

- **HTML**（含内嵌 JS）：是你写的“程序”，控制界面和逻辑；修改它等于改规则。
- **JSON 备份**：是某时刻数据的“快照”；复制/回滚 HTML 代码，不会自动带走浏览器里已保存的 localStorage 记录。
- 这意味着：
- 你把自己改好的工具发给朋友，他需要同样在本地用 HTTP 服务（或类似环境）打开，并且浏览器里要有相同的存储键；但**不需要**他的浏览器已经存在同名键或记录。目标环境可以是空的，导入/导出功能会处理兼容格式。若使用本地 HTTP 服务，是各自在自己的电脑启动，交换 HTML 不会自动复制记录；要另外传递合适保存的 JSON。
  - 只是“交换文件”不等于“备份数据”，必须真正下载并导入那个 JSON。

### 2. localStorage 的隔离与持久性

- 按 **origin**（协议 + 主机 + 端口）隔离：
- localhost 与 127.0.0.1 的 host 不同导致 origin 不同，因此即便访问同一台电脑，localStorage 也不会共享：`http://localhost:8765` 和 `http://127.0.0.1:8765` 被视为两个不同的源。来源：[MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)。
  - `file:///...` 行为不统一，不建议依赖它来做可靠的跨标签页共享。
- 按 **浏览器配置/隐私窗口** 隔离：
  - 普通标签页共享同一个配置下的 localStorage；
  - 隐私/无痕窗口通常独立，关闭所有隐私窗口后其数据可能清除；
  - 这意味着：**“下载 JSON 备份”仍然是必须的**，不能以为“只改工具 URL 就能跨设备迁移”。

### 3. 刷新与缓存不是“清除数据”

- 刷新页面：调用 localStorage 读取/写入，不会直接清空它。
- 清除浏览器缓存（图片、资源）：不影响 localStorage。
- 真正的清除需要：
  - 在开发者工具中手动选择“清除网站数据”；
  - 或在系统设置里删除该 origin 的 localStorage / IndexedDB；
  - 或者使用隐私窗口的“关闭后清除所有数据”功能。

### 4. JSON 可读且无加密

- 备份文件是纯文本 JSON，任何人可以用文本编辑器打开查看；
- 它能被任何兼容的导入工具读取，但不保证：
  - 未来版本一定支持相同结构；
  - 第三方应用一定能正确恢复（除非你公开规范）。
- 对于重要数据：
  - 导出后建议额外保存一份到电脑硬盘或云存储；
  - 再更改打开地址或升级工具前，先保留独立备份、核对后再操作。

## 九、完整操作路径回顾（你可直接照着做一遍）

把上面的内容浓缩成一套可执行的操作清单：

1. **环境准备**
   - 新建练习目录，放入 `starter.html` / `expense-tool.html` / `sample-backup.json`；
   - 终端启动服务：`python3 -m http.server 8765 --bind 127.0.0.1`。

2. **熟悉与录入**
   - 用 starter.html（或你的修改版）在同一浏览器打开；
   - 录入三笔虚构支出：Lunch 12.50、Bus 8.00、Notebook 5.00；
   - 刷新核对：3 笔，合计 25.50 元，逐字段无误。

3. **导出备份**
   - 点击“导出备份”，得到 `expenses-backup.json`（建议先检查页面显示只有 3 笔再导出）；
   - 在下载列表和文件管理器中确认真实生成；
   - 用文本编辑器打开 JSON，核对结构、日期、金额。

4. **空环境恢复验证**
   - 用隐私窗口/独立配置打开工具；
   - 确认初始为 0 笔；
   - 选择导出的 JSON，校验通过后确认恢复；
   - 刷新：仍为 3 笔、25.50 元，逐条核对。

5. **再导入同一备份**
   - 当前仍显示 3 笔直接重复导入同一个旧备份：结果仍为 3 笔/25.50 元；
   - 再添加 Coffee 1.00 元，变为 4 笔/26.50 元；
   - 使用“取消恢复”功能可保持 4 笔/26.50 元不变；
   - 如需长期保留 4 笔，请另导出并与旧文件区分命名；
   - 最后确认原备份再次替换导入，刷新后回到 3 笔/25.50 元（Coffee 不在其中）。

6. **错误文件测试**
   - 修改 version 为 2，或破坏 JSON 语法；
   - 选择该文件：应提示校验失败且不清空记录；
   - 刷新：原记录仍存在。
